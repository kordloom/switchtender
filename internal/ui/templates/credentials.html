Federation signing keys

Clouds verify each run's identity token against these keys. Each key's private half is sealed with this server's encryption key, which lives outside the database.

Key id State Created Starts signing Stops signing Leaves the key set
Normal or emergency rotation

Rotate publishes a new key now and starts signing with it in 24 hours. The current key keeps signing until then and stays published for 24 hours after. Clouds have a day to fetch the new key before any token needs it, and every token the old key signed expires while that key is still published. Use it for routine rotation.

Emergency rotation is for a key that may be compromised. A new key signs at once, and every other key leaves the published set at the same moment with its private half erased, not only the one signing: a key a normal rotation published and has not started signing with goes too, and so does any retired key still published. They are all stored the same way, so a suspected compromise of one is treated as a compromise of all, and nothing they signed verifies again. The cost is failed runs: a run holding a token from a removed key fails, and a run that starts before a cloud has fetched the new key fails until it has. Use it when a forged token would be worse than failed runs.

Emergency rotation

A new key starts signing now, and every other key leaves the published set at once, not only the one signing. Use this when a signing key may be compromised.

That includes a key a normal rotation published and has not started signing with yet, and any retired key still published. They are all stored the same way, so a suspected compromise of one is treated as a compromise of all.

Runs fail for a while. A run holding a token from a removed key fails as soon as the cloud reads the new key set, and a run that starts before a cloud has fetched the new key fails until it has.

This cannot be undone. The removed keys' private halves are erased.

SwitchTender is starting{{ if .Values.database.dsn }} on PostgreSQL{{ else }} on SQLite, with the whole install on the volume {{ include "switchtender.fullname" . }}-data{{ end }}.

Reach the interface:

  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "switchtender.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}

then open http://127.0.0.1:{{ .Values.service.port }}.

The first server to start writes an initial admin token to /data in its pod, readable by the service
user alone:

  kubectl exec -n {{ .Release.Namespace }} deploy/{{ include "switchtender.fullname" . }}-server -- cat /data/initial-admin-token

Sign in with it, create named accounts and tokens, then delete it.

Keep the encryption key and salt this install was given. Every stored credential is sealed against
them, and a new salt on an upgrade leaves those credentials unreadable. helm uninstall leaves the data
volume and the Secret holding the keys in place.

The pods run {{ include "switchtender.image" . }}. The release workflow signs and attests each image
by digest, and the chart can pin that digest so every pod runs exactly the image that was verified.
Check the image, then set image.digest to the sha256 both commands report:

  cosign verify {{ include "switchtender.image" . }} \
    --certificate-identity-regexp '^https://github.com/kordloom/switchtender/\.github/workflows/release\.yml@refs/tags/v' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
  gh attestation verify oci://{{ include "switchtender.image" . }} --repo kordloom/switchtender
  helm upgrade {{ .Release.Name }} <chart> --reuse-values --set image.digest=sha256:<digest>
{{- end }}
